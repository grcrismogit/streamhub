    Antes de empezar

    Prepara la cuenta y sube el código a GitHub, porque la instancia EC2 lo descargará desde ahí.

    1. Entra a tu curso en AWS Academy → Modules → Launch AWS Academy Learner Lab.
    2. Pulsa Start Lab y espera a que el círculo junto a “AWS” se ponga verde (1–3 minutos).
    3. Haz clic en AWS (el texto con el círculo verde). Se abre la consola de AWS en otra pestaña.
    4. Arriba a la derecha comprueba que la región sea N. Virginia (us-east-1).
    5. En la página del laboratorio pulsa AWS Details → junto a SSH key pulsa Download PEM. Guarda labsuser.pem en tu carpeta Descargas.
    Importante

    En Learner Lab no puedes crear roles IAM; usarás el perfil que ya existe, LabInstanceProfile. La sesión dura unas horas; si se acaba, vuelve a pulsar Start Lab y revisa que tus recursos estén encendidos.

    1. Inicia sesión en console.aws.amazon.com.
    2. Arriba a la derecha, en el selector de región, elige US East (N. Virginia) us-east-1. Crea todo en la misma región.

    1. En GitHub pulsa New repository, nómbralo streamhub, márcalo Public y no agregues README (ya existe).

    Fase 1

    Security Groups (firewalls)

    Un Security Group decide qué tráfico puede entrar a un recurso. Crearás dos: uno para la API (abierto a internet en el puerto 80) y otro para la base de datos (solo acepta conexiones que vengan de la API).

    Consolabuscador: EC2Network & SecuritySecurity GroupsCreate security group

    Security group namesg-streamhub-api
    DescriptionAPI StreamHub
    VPCLa que aparece por defecto (default)
    Inbound rule 1Type HTTP · Source Anywhere-IPv4 (0.0.0.0/0)
    Inbound rule 2Type SSH · Source My IP
    Outbound rulesDéjalas como están

    Pulsa Add rule para cada regla de entrada y al final Create security group.

    Security group namesg-streamhub-db
    DescriptionBase de datos StreamHub
    VPCLa misma default
    Inbound ruleType PostgreSQL (puerto 5432) · Source Custom → en el buscador escribe sg- y elige sg-streamhub-api
    Por qué así

    Al usar el Security Group de la API como origen, solo la instancia EC2 puede hablar con la base de datos. Ni tú ni nadie en internet puede conectarse directo.

    Deberías ver

    Dos grupos en la lista. En sg-streamhub-db, la regla de entrada muestra como origen un ID que empieza por sg-.

    No aparece sg-streamhub-api en el buscador

    Fase 3

    Los tres buckets de S3

    El nombre de un bucket es único en todo el mundo; por eso cada uno lleva tu sufijo. El bucket del frontend es público (es un sitio web). Los de videos y miniaturas son privados: la API entrega enlaces temporales para verlos.

    Consolabuscador: S3BucketsCreate bucket

    Bucket typeGeneral purpose
    Bucket name{{frontend}}
    Object OwnershipACLs disabled
    Block Public AccessDesmarca “Block all public access” y marca la casilla de confirmación de abajo
    Versioning / EncryptionComo están (Disable · SSE-S3)

    Pulsa Create bucket.

    1. Abre el bucket {{frontend}} → pestaña Properties → baja hasta Static website hosting → Edit.
    2. Enable · Hosting type Host a static website.
    3. Index document: index.html · Error document: index.html.
    4. Save changes.
    Por qué index.html dos veces

    Así, si alguien recarga /watch/5, S3 devuelve la app y React muestra la página correcta en vez de un error 404.

    Deberías ver

    Al final de Properties, un Bucket website endpoint: {{website}}. Si el tuyo es distinto, usa el de la consola.

    Fase 4

    Permisos con un IAM Role

    La API necesita subir y borrar archivos en S3. En lugar de poner claves en el código, la instancia EC2 recibe un rol y AWS le entrega credenciales temporales automáticamente.

    No hay nada que crear. En el paso 5.1 elegirás LabInstanceProfile como IAM instance profile. Ese rol ya tiene permiso para usar S3.

    Para tu informe

    Explica que en un entorno real crearías una política de mínimo privilegio (la tienes en infra/aws/iam-ec2-s3-policy.json) y que el laboratorio no permite crear roles.

    Consolabuscador: IAMPoliciesCreate policypestaña JSON

    Borra lo que haya en el editor y pega:

    JSON
    {
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "StreamHubMediaObjects",
      "Effect": "Allow",
      "Action": ["s3:PutObject", "s3:GetObject", "s3:DeleteObject"],
      "Resource": [
        "arn:aws:s3:::{{videos}}/*",
        "arn:aws:s3:::{{thumbs}}/*"
      ]
    }
  ]
}

    Next → Policy name StreamHubS3MediaAccess → Create policy.

    Mínimo privilegio

    La API solo puede subir, leer y borrar objetos en esos dos buckets. No puede tocar el frontend ni ningún otro servicio.

    1. IAM → Roles → Create role.
    2. Trusted entity type AWS service · Use case EC2 → Next.
    3. Busca StreamHubS3MediaAccess, márcala → Next.
    4. Role name StreamHubEC2Role → Create role.

    Sin IP elástica, la IP pública cambia cada vez que la instancia se detiene, y tendrías que recompilar el frontend.

icacls.exe {{keyfile}} /grant:r "$($env:USERNAME):(R)"
icacls.exe {{keyfile}} /inheritance:r
ssh -i {{keyfile}} ec2-user@{{eip}}

    macOS / Linux:

    Bash
    cd ~/Downloads
chmod 400 {{keyfile}}
ssh -i {{keyfile}} ec2-user@{{eip}}

    Si pregunta Are you sure you want to continue connecting? escribe yes y Enter.

    Connection timed out
    Tu IP cambió (por ejemplo, otra red Wi-Fi). Edita sg-streamhub-api → regla SSH → Source “My IP” de nuevo.
    UNPROTECTED PRIVATE KEY FILE / Permission denied (publickey)

    La instancia no tiene rol. EC2 → selecciona streamhub-api → Actions → Security → Modify IAM role → elige el rol → Update.

    Fase 6

    Instalar la API en EC2

    Un script instala Python, Nginx y la API como servicio, crea las tablas en RDS y prueba la conexión con S3. Todo esto se ejecuta dentro de la sesión SSH.

    EC2
    sudo dnf install -y git
git clone {{repo}}.git /tmp/streamhub
sudo REPO_URL={{repo}}.git bash /tmp/streamhub/backend/deploy/setup_ec2.sh
    Deberías ver

    Al final: !! /etc/streamhub/api.env todavía tiene valores de ejemplo. Es normal: el script se detiene para que completes la configuración. Ya generó una clave JWT aleatoria por ti.

    Este comando escribe tus datos en /etc/streamhub/api.env. Copia y pega tal cual:

    EC2
    sudo sed -i \
  -e "s|^ENVIRONMENT=.*|ENVIRONMENT=production|" \
  -e "s|^CORS_ORIGINS=.*|CORS_ORIGINS={{website}}|" \
  -e "s|^DB_HOST=.*|DB_HOST={{rds}}|" \
  -e "s|^DB_USER=.*|DB_USER=streamhub_admin|" \
  -e "s|^DB_SSLMODE=.*|DB_SSLMODE=require|" \
  -e "s|^AWS_REGION=.*|AWS_REGION={{region}}|" \
  -e "s|^S3_VIDEOS_BUCKET=.*|S3_VIDEOS_BUCKET={{videos}}|" \
  -e "s|^S3_THUMBNAILS_BUCKET=.*|S3_THUMBNAILS_BUCKET={{thumbs}}|" \
  /etc/streamhub/api.env

    Ahora la contraseña de RDS. Escribe este comando a mano reemplazando TuClaveDeRDS por la tuya (así no queda guardada en ningún sitio web):

    EC2
    sudo sed -i "s|^DB_PASSWORD=.*|DB_PASSWORD=TuClaveDeRDS|" /etc/streamhub/api.env

    Revisa el resultado:

    EC2
    sudo grep -v '^#' /etc/streamhub/api.env | grep .
    Deberías ver

    Tus valores reales en CORS_ORIGINS, DB_HOST y los buckets, JWT_SECRET_KEY con una cadena larga y ninguna línea AWS_ACCESS_KEY_ID.

    Alternativa con editor

    sudo nano /etc/streamhub/api.env · muévete con las flechas · guarda con Ctrl+O y Enter · sal con Ctrl+X.

    Ojo con CORS

    CORS_ORIGINS debe ser exactamente la URL del sitio: con http:// y sin / al final. Si no coincide, el navegador bloquea las llamadas a la API.

    EC2
    sudo REPO_URL={{repo}}.git bash /tmp/streamhub/backend/deploy/setup_ec2.sh

    Compilar y publicar el frontend

    Esto se hace en tu computadora (necesitas Node.js 20 o superior). La dirección de la API se incrusta al compilar, por eso primero la configuras.

    Abre una terminal nueva en tu PC (no la de SSH), dentro de la carpeta streamhub\frontend:

    macOS / Linux

npm install
npm run build
    Deberías ver

    ✓ built in … y una carpeta nueva dist/ con index.html, favicon.svg y assets/.

    1. S3 → bucket {{frontend}} → Upload.
    2. Add files → elige index.html y favicon.svg de dentro de dist.
    3. Add folder → elige la carpeta assets de dentro de dist.
    4. Upload → Close.
    No subas

    La carpeta dist en sí, ni src/, node_modules/ o package.json. En la raíz del bucket deben quedar exactamente index.html, favicon.svg y assets/.
